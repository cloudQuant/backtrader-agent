# 迭代 001：可信执行与发行契约

本目录是 `backtrader-agent` 首个发布后改进迭代的范围权威。它把已复现的安全、发行物和可维护性缺口拆成可实现、可验收的工作，而不改变产品的离线优先、确定性和双审批边界。

## 基线证据

- 基线提交：`adc81a9`，干净 `master` 工作树。
- Python 3.11 与 Python 3.8 均已本地执行 `pytest tests -q -p no:cacheprovider`，各通过 59 项；这证明最低版本可以运行，但 CI 尚未持续证明它。
- `validate` 目前允许调用方给出任意 `--engine-hash` 和 `--environment-hash`，无已注册引擎根时仍可完成真实子进程运行；该路径与项目的“已批准引擎根”声明不一致。
- 生成的 `run.py` 无条件导入 `backtrader` 与 `pandas`，但发行物的运行依赖没有以可安装 extra 发布，CI 以手工依赖列表掩盖了该缺口。

## 许可证基线

维护者已明确指定 MIT 为权威许可证。本迭代将 `pyproject.toml` 元数据与现有 MIT `LICENSE` 文本统一，并以 wheel 元数据测试防止再次漂移；不改变许可证文本或发布版本。

## 明确不在本轮范围内

- 不引入在线行情、券商、实盘交易、模型 API、任意候选代码执行或操作系统沙箱。
- 不实现跨进程会话锁；该已复现的并发缺口作为下一轮的独立需求，避免与执行契约重构耦合。
- 不把 `entry`、`exit`、`sizing`、`risk` 自由文本翻译成策略逻辑；本轮保持固定脚手架的确定性边界。
